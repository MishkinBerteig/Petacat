# Episodic Implementation Evidence

Reviewed 2026-09-06. This note maps the added manuscript discussion of
episodic-memory mechanisms to the current repository. It is a source and test
definition review, not a new engine experiment or a claim that the historical
measurement files were generated by this exact source revision.

## What Was Added to the Paper

The learning-mode case study now distinguishes direct cross-run search feedback
from retrospective reminding and explanation, describes existing
memory-specific regression contracts, and explains why an answer-letter oracle
cannot establish rule-level memory fidelity. The expensive reusable reference
and smaller repeated check remain the contribution being evaluated. For the
archived learning protocol, the stated budget ratio is 5:1 in whole episodes,
not the approximately 197:1 ratio from the separate single-run study.

## Existing Regression Definitions

No tests in this section were executed by this review. Names identify assertions
that already exist, not newly witnessed passing results.

  contains same-answer/same-rule, different-rule, and different-problem cases
  for `answer_present`. It also checks memory-scoped identifiers and identifier
  reset on clear. The duplicate tests patch rule-signature extraction with
  explicit test signatures; they do not independently validate the extractor.
- [tests/module/test_justify_and_jootsing.py](../tests/module/test_justify_and_jootsing.py)
  includes
  `test_an_answer_already_in_memory_stops_the_jootser_settling_for_it_again`.
  Its memory double always reports a hit; it checks the recovery branch's

- [tests/seed_unit/test_episodic_memory.py](../tests/seed_unit/test_episodic_memory.py)
  checks exact-threshold exclusion, graded activation, distance arithmetic,
  the distinction between differing and unique themes, snag justification,

  structurally different rules with identical prose, including the fallback
  description `Unknown transformation`, do not collide as snags. Missing snag
  signatures and different problems are checked separately.
- [tests/module/test_dissertation_parity.py](../tests/module/test_dissertation_parity.py),
  `TestMemory`, contains hand-constructed tests for theme classification,
  reminding selectivity, activation, snag-based reclassification, and English

  they are not live Scheme/Python differential tests.
- [tests/unit/test_compare_harness.py](../tests/unit/test_compare_harness.py)
  verifies the last-success projection, skipping capped and answerless runs,

## Historical Results and Attribution

The ordered port sequences and their arithmetic audit support 1,900 eight-run
episodes per archived cycle. The CPU before/after records contain 17 versus 13
stored novel input/endpoint pairs, in 28 versus 14 episodes, with no missing
stored head member. Their respective capped-run counts are 1,311 and 2,404.
These are paired saved records, not independent new replications.

[DISCREPANCIES4.md](../DISCREPANCIES4.md), the RC-A investigation and its
implementation report, associates removal of several episodic novel outcomes
with the direction-sensitive image repair. That repair is not itself an
episodic-memory algorithm change. The current memory regression definitions
must not be described as additional causal explanations for the before/after
count reduction without a versioned experiment that isolates them.

[DISCREPANCIES3.md](../DISCREPANCIES3.md), "Engine changes since the oracle
re-run", reports three further fixes for string handling and says they left
same-seed measurements byte-identical. This is useful historical context, not
independent confirmation that every current memory feature was tested in the
archived cycles. Historical suite counts in either development report were
not independently reproduced by this review.

## Claims That Must Stay Qualified

- The historical episodic reference is absent from the arithmetic supplement.
  Its reported 9,500-episode size and membership labels are not independently
  reconstructed from raw reference episodes here.
- The port episode cap is 20,000 codelets per run; the reported reference cap
  is 100,000. An early cap can change all later memory-dependent behavior.
  Similar aggregate cap rates would not remove this confound.
- `convergence_answer` is a legacy function name for the last successful answer
  within a fixed eight-run horizon. It neither establishes convergence nor
  includes the four never-answering episodes per cycle in its endpoint
  histogram. The manuscript reports those omissions explicitly.
- Before/after cycles reuse seeds, and episodic seeds overlap the single-run
  seed block. They are paired replays, not independent evidence across modes.
- A string observed in a fresh-memory reference is not thereby validated for
  a particular learned history. The 11 post-repair novel episodic pairs also
  seen in the single-run reference remain episodic discrepancies.
- Recurrence does not prove invalidity, and an empirical singleton ratio is
  not a confidence bound. Claims in older reports that recurrence settles a
  defect, that missing-head false-alarm probability is exactly zero, or that
  Good--Turing determines how many novel episodes a correct port must produce
  should not be imported into the paper.
- Fewer flagged endpoints do not establish better learning. The saved CPU
  capped-run count rises after repair. Rule identities, duplicate rejection
  events, reminding activations, and memory updates are not retained in the
  archived eight-state sequences, so those records cannot establish
  fidelity of the underlying memory trajectories.

The needed next evidence is a separately versioned, matched-cap learning-mode
study with independent reset episodes, complete declared outcome projections,
retained memory-specific traces, and explicit memory-retained, memory-cleared,
and known-defect controls. That evaluation should measure both the upfront
reference investment and the repeated-check cost; it has not been represented
as completed in this revision.
